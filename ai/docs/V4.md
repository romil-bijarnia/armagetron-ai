# V4 combat architecture

V4 is the only supported network and checkpoint format. The implementation is
`PolicyNet` in `arma_ai/model.py`; training is in `arma_ai/teach.py`.

V4 has **8,155,373 parameters**, six joint steering/brake controls, separate spatial scales, arena-conditioned local features, an explicit opponent branch and persistent 256-unit recurrent memory. Its output heads learn policy, bounded round value, territory, danger, successful attack forecasts and future ownership.

The architecture is intended to support sustained pressure, precise close fights and decisive attacks. Playing strength and style still come from training. New V4 runs start at update 0; the existing `runs/blacklight` checkpoint has already trained and resumes from its saved update. Validation uses separate temporary runs.

## Controls

| Code | Steering | Brake |
| --- | --- | --- |
| 0 | Straight | Off |
| 1 | Left | Off |
| 2 | Right | Off |
| 3 | Straight | On |
| 4 | Left | On |
| 5 | Right | On |

Both brake-turn actions obey the same turn delay and legality checks as their unbraked counterparts. Combined turns retain the brake on subsequent straight decisions when requested. The simulator and real engine apply the same controls. Wire protocol 4 carries 108 scalar inputs and the same six controls. Checkpoints require observation_version=2; the original 96 input positions and all action codes keep their meanings.

## Network

| Branch | Processing | Output |
| --- | --- | --- |
| Nearby, 2 m cells | Current + previous frame; 3×3/stride-2 stem to 48×32×32; residual processing at 32×32; reduction to 64×16×16; 3 residual blocks, including global pooling; arena conditioning; downsample and project | 192 |
| Close, 1 m cells | Its own weights and the same progressive structure | 192 |
| Arena + territory | Current + previous frame; 128×16×16; 5 residual blocks, global pooling, learned positions and 2 four-head attention layers | 256 |
| Own/arena numbers | 72 inputs: original scalar indices 0–63 and 88–95, including eight reserved slots; two 256-wide layers | 256 |
| Opponents | Three 12-number enemy records; shared 12→64→64 encoder; context query; masked attention pooling | 64 |
| Fusion | Concatenate 192 + 192 + 256 + 256 + 64 = 960; two 768-wide layers | 768 |
| Memory | 768 fused features + previous executed six-action one-hot + elapsed time; GRU 775→256; residual projection 256→768 | 768 remembered features; 256 carried state |

The 1 m and 2 m grids no longer enter one convolution as if the same cell index meant the same physical position. Each gets its own filters and a full residual block at 32×32 before reduction. This increases the processing available for wall edges and gaps; it does not undo the observation grid’s original resolution limit. Exact ray distances remain available through the number branch.

The arena summary adjusts the gain and bias of both local feature maps before they are compressed into summaries. This is bounded feature-wise conditioning, related to [FiLM](https://arxiv.org/abs/1709.07871): gain is `1 + 0.1 × tanh(gain)` and bias is `0.1 × tanh(bias)`. It begins as an identity transformation. That gives local tactics access to global space while keeping the initial modulation stable.

Opponent measurements go exclusively through the shared opponent encoder. They cannot bypass it through the ordinary number branch. The query depends on the spatial summaries and own/arena measurements. Absent enemies have exactly zero weight, including in float16; permuting the three enemy records leaves the final policy and value unchanged. The input still contains only the three nearest enemies, which covers every opponent in the current four-player training arenas.

Two map frames still provide immediate motion information. A 256-unit GRU also
carries state throughout each player's life. It receives the previous executed
control and elapsed game time divided by 0.05 seconds. Controls ignored at time
zero or rejected by legality checks are not presented as executed turns. Memory
resets on a new life, changed model or discontinuous observations; duplicate
delivery does not consume the observation twice. This is a learned summary, not
a fixed target lock or a guarantee that the untrained memory branch improves play.

The memory projection begins at zero. Migration preserves every existing model
tensor and compatible optimizer moment, so the added branch initially preserves
Blacklight's previous behavior. `arma_ai/migrate_memory.py` performs the explicit,
versioned conversion to `memory_version=1` without resetting training counters.

## Heads and learning signals

- **Policy:** six logits, legal-action masking, then softmax. Turning while braking is an actual executable move.
- **Value:** a scalar passed through `tanh`, bounded to −1…+1 and trained on discounted round outcome. It remains a score, not a calibrated win probability.
- **Territory:** expected territory share two seconds ahead.
- **Danger:** probability of own death within two seconds.
- **Attack:** probability of receiving a credited enemy kill within two seconds **and remaining alive through that horizon**. Mutual death and posthumous kills receive no credit for this target; an early surviving terminal win can receive credit.
- **Ownership:** three classes over the arena’s 16×16 features; training enlarges the logits to 64×64, as in the earlier system.

The extra attack target is wired through the simulator, shared replay, loss and inspector. It trains combat-relevant features used by the policy. The actor-critic objective uses discounted round outcome, which favors earlier wins. There is no raw kill bonus that would pay for a suicidal trade. The [KataGo work](https://arxiv.org/abs/1902.10565) supports the general use of global context and auxiliary spatial supervision; benefits in Tron still need measured training comparisons.

## Training

The fighter curriculum starts half of the duels in varied parallel, crossing or
offset head-on encounters; the other duels and four-player games retain standard
spawns. `--combat-prob` controls that fraction. Spawn changes use normal physics,
resources and observations, reset temporal history, and happen before the first
decision. Three rounds in ten are against the space fighter (`--hunter-prob`),
the cutting opponent, and two in ten involve the exploiter (`--exploiter-prob`).

The exploiter is a copy of the current network that trains against a frozen
copy of it, the target, looking for what beats it. Half of its rounds
(`--exploiter-train-share`) are that training: the exploiter plays the target
and only the exploiter learns. The other half are the main network against the
current exploiter, and only the main network learns, so what the exploiter finds
reaches the main network. The two scores are kept apart: `win_exploiter` is the
exploiter's score against the target and `win_vs_exploiter` the main network's
against the exploiter, both in the metrics report, the learner's console line
and the outcome counts, beside the space fighter's `win_vs_hunter`. Promotion is
judged from the exploiter's own rounds alone: once it scores `--exploiter-win`
over its last `--exploiter-games` of them, or after `--exploiter-patience`
updates, a new exploiter starts from the current network against a new target,
and the rounds of an older exploiter still in play cannot promote the new one.
Until 20 October 2026 every exploiter round was its own training, so one round
in five taught the main network nothing.

Whether the exploiter is learning at all is visible without reading the
checkpoint. `progress.json` carries an `exploiter` record with its generation,
what its learning loop did last (`warming_up`, `caught_up`, `waiting_for_ready`
or `learning`), its updates against its patience, its updates this session, and
the fresh and ready direct-policy samples of its own generation against what a batch
needs. Each metrics report repeats the generation, the updates, the updates this
session, the phase and the samples generated, trained and ready as `exploiter_*`
fields.

The objective is the discounted round outcome with a discount of 0.997 per
decision (`--gamma`): a win ten seconds away is worth 55% of an immediate one,
and a win thirty seconds away 16%, so both the policy and the value head prefer
finishing a fight to sitting on a lead. Since 19 October 2026; the earlier
0.999 left a win ten seconds away worth 82%.

Blacklight samples its own legal actions without lookahead. Replay retains the executed
control, its log probability under the actor's temperature-scaled distribution,
the actor's value estimate and weight update. The advantage is the discounted
n-step return minus that recorded value. A clipped likelihood-ratio actor-critic
loss reinforces better-than-predicted outcomes and discourages worse outcomes;
an entropy bonus maintains exploration. Value and auxiliary losses are retained.
The clipped surrogate follows [PPO](https://arxiv.org/abs/1707.06347); this trainer
uses asynchronous recurrent replay with a bounded policy age rather than PPO's
synchronous rollout epochs.

`--policy-clip` defaults to 0.2, `--entropy-coef` to 0.01, and
`--max-policy-lag` to 64 learner updates. Searched decisions and older policies
are excluded from learning. Warmup requires collected positions and ready direct
policy targets, with no search-target gate. The trainer has no `--sims`, `--macro`,
`--search-prob` or `--gumbel` options. On the first resume after removing the
search teacher, learned model weights and cumulative counters survive; optimizer
moments reset because the objective changed. Later sessions restore the new
objective's optimizer state exactly. The architecture is unchanged.

The simulator still exposes its former Gumbel search for isolated inspection and
regression checks. It completes unvisited action values with a prior-weighted
value mix, rescales legal Q values to [0, 1], adds `(50 + max visits) * 0.1`
scaled bonuses to network logits, and narrows root candidates with Gumbel noise
and sequential halving. Below the root, selection follows improved probability
minus visit proportion. Joint-action branches advance the actual physics and
bootstrap network values at new leaves; discounted returns back up through each
branch. Hunter branches stop at its next unknown replan. This algorithm supplies
neither moves nor targets to the trainer. `python -m arma_ai.search_trace
--output runtime/search-trace.json` records an isolated checkpoint search without
writing replay or weights.

Both learners use contiguous sequences, with burn-in to reconstruct state and a
learned unroll. RL defaults to 16 burn-in and 32 learned decisions. Its actor
keeps a consistent weight generation within each life. Imitation uses the same
default horizons, validates with whole-life state, and additionally preserves
value/auxiliary/ownership predictions while adapting shared features. Freezing
head weights alone would not preserve predictions from changing shared features.

`uv run arma-background` and `uv run arma-full` both use `runs/blacklight` for the trainer, logs, supervisor and the one saved checkpoint, `latest.pt`. Background uses 96 simultaneous arenas, four simulator threads, batch 256, lower CPU priority and a 35% work/rest target for each worker. Full uses 256 arenas, all available CPU cores and batch 512 without that pacing. See the [training modes](../README.md#training) for limits and overrides. A fresh v4 run explores all six actions from the beginning.

`--max-updates N` is a bounded validation option for the trainer: it stops at total update N and saves a resumable checkpoint. Zero means unlimited. Impossible replay-ring capacities are rejected before allocation rather than leaving a run waiting forever for samples it cannot retain.

## Verification

The suite covers V4 float32/float16 C++ parity, temporal reset, six-action masks,
bounded value, conditioning, opponent attention and exact inspector activations.
Enemy-order invariance and absent-enemy exclusion are tested. Policy gradients
reach every map/frame and scalar branch. Temporary CPU and Apple GPU runs test
learning, checkpoint saving, optimizer restoration and continued training.

Recorded real-engine rounds agree with the simulator for steering and combined
braking controls, including masks, headings, positions, deaths and observations.
Close-encounter starts use the same observation and physics paths. Search tests
cover known hunter controls, a lethal-cut regression, cutoff timing and history.

Before observation revision 2, the V4-only cleanup preserved all 138 state tensors and 7,164,397 parameters. The input upgrade adds one observation-version marker and 256 zero-initialized connection weights; it retains the existing learned tensors and expands the corresponding optimizer moments with zeros.
A frozen production checkpoint produced bitwise-identical forward, auxiliary-head
and greedy-action outputs before and after cleanup in float32 and float16. Its
native exports were also byte-identical. Retired checkpoint formats are rejected.

The Decision view exposes all six controls and the attack forecast. Input tests separately remove own/arena numbers and enemy measurements.

The validation runs establish that the pipeline works; playing strength needs longer training and evaluation against fixed built-in opponents and the space fighter, varied arena sizes, and focused close-combat situations. Compare attack frequency, credited kills, deaths, round length and wins together.

## Checkpoint continuity

RL and imitation share `runs/blacklight/latest.pt`, weights, and the cumulative update
count. Imitation restores its optimizer across imitation sessions; changing
training methods resets stale optimizer moments but retains learned weights.
Both learners hold the same exclusive writer lock. RL keeps a copy of the
checkpoint in `snapshots/` once per `--snapshot-every` updates (default 1000)
to fall back on; it never resumes from one by itself, and its temporary worker
copies are removed on shutdown. Separate test directories are disposable, not
alternative active AIs.

## Opponent input revision 2

The original 96 scalar positions are retained. Fields 96–107 contain four additional
measurements for each of the three enemy slots, in the same order as their original
eight-field records: braking reservoir, used rubber divided by its budget, left-turn
wait and right-turn wait. Waits are remaining legal-turn time divided by that
cycle's turn delay, clamped to 0–1. Zero means the direction is ready. Absent
opponents have all-zero extra fields. The own/arena branch still reads exactly
0–63 and 88–95; enemy features cannot bypass the opponent encoder.

The migration expands only `opponents.0.weight` from 64×8 to 64×12 and zero-pads
matching Adam moments. Compatible main/helper weights, global updates, imitation
counters and optimizer steps are preserved. On 160 recorded observations, all
chosen actions remained unchanged. Native/Python float16 and float32 comparisons
exercise nonzero extra connections, and engine/simulator tests verify the new
measurements. Fresh demonstrations carry their observation version explicitly;
old 96-input recordings are rejected rather than silently filled with invented data.

A separate experiment in `arma_ai/memory_experiment.py` tested a 256-unit GRU
with 985,344 added parameters against a matched stateless adapter. Memory improved
two small-arena fighting situations, but larger fights ended in stalemates and
exact teacher-turn recall did not improve. All six paired situations completed;
see the [experiment results](BLACKLIGHT-ARCHITECTURE-REVIEW.md#memory-experiment).
That frozen-feature policy-only prototype remains a historical experiment and
does not write persistent model checkpoints. Production now uses the integrated,
action/time-aware GRU shared by policy, value and vector auxiliary heads. Its
newly migrated memory must learn through subsequent training; the prototype's
mixed combat results are not a production win-rate claim.
